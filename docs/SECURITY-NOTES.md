# Известные уязвимости зависимостей

Файл ведётся вручную. Проверка: `npm audit`.
Последняя проверка: 26 июля 2026.

## Исправлено

| Пакет             | Проблема                                   | Решение                  |
| ----------------- | ------------------------------------------ | ------------------------ |
| `@fastify/static` | Обход авторизации и path traversal (4 CVE) | Поднят до `^10.1.2`      |
| `@nestjs/swagger` | Несовместимость с NestJS 11                | Поднят с `^8` до `^11.4` |
| `next`            | Уязвимости сборки и обработки изображений  | Поднят с 15 до `^16.2`   |

## Остаточные (исправление зависит от апстрима)

Все перечисленные пакеты подтянуты транзитивно и зафиксированы вложенными копиями
внутри `next` и `@nestjs/platform-fastify`. `npm overrides` в текущей конфигурации
npm 11 + workspaces не применяются (проверено: переопределение игнорируется),
поэтому закрыть их можно только выпуском обновлений апстримом.

| Пакет                                                   | Проблема                                | Достижима ли в нашей конфигурации                                                  |
| ------------------------------------------------------- | --------------------------------------- | ---------------------------------------------------------------------------------- |
| `sharp` 0.34.5 (внутри `next`)                          | CVE в libvips при обработке изображений | Пока нет — загрузки изображений появятся на этапе 2. **Пересмотреть на этапе 2.**  |
| `find-my-way` 9.6.0 (внутри `@nestjs/platform-fastify`) | DDoS через HTTP/2                       | Нет — API работает по HTTP/1.1 за nginx/Plesk                                      |
| `postcss` 8.4.31 (внутри `next`)                        | Path traversal через sourceMappingURL   | Нет — обрабатывает только наш собственный CSS на этапе сборки                      |
| `js-yaml`, `brace-expansion`                            | DoS при разборе                         | Нет — только инструменты разработки (ESLint, Jest), в продакшен-сборку не попадают |

## Регламент

1. `npm audit` запускается вручную перед каждым релизом.
2. Перед этапом 2 (загрузка фотографий товаров) — перепроверить `sharp`.
3. На этапе 12 (безопасность и запуск) — полный аудит с актуальными версиями.
