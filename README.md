# QAZAQ TAS GROUP — Digital ERP

Единая цифровая система управления производственной компанией QAZAQ TAS GROUP
(производство изделий из мраморного композита: брусчатка, бордюры, дренажные системы, МАФ, натуральный камень, благоустройство).

---

## 1. Суть проекта

Это не просто сайт и интернет-магазин. Это **единая ERP-платформа**, в которой весь бизнес работает в одной системе:

**Клиент → Лид → Продажи → Производство → Склад → Логистика → Финансы → Аналитика → AI**

Каждый процесс связан с другим. Система заменяет множество отдельных программ
(CRM, склад, производственный учёт, бухгалтерию, мессенджеры) единым цифровым управлением компанией.

Главная цель — **цифровой завод**, где любой заказ проходит полный путь:

```
Клиент написал
    ↓
Система создала лид
    ↓
Менеджер сделал расчёт
    ↓
Клиент подтвердил
    ↓
ERP создала заказ
    ↓
Производство получило задачу
    ↓
Склад подготовил материалы
    ↓
Изделие изготовлено
    ↓
Контроль качества
    ↓
Доставка
    ↓
Клиент получил товар
    ↓
Финансы получили отчёт
```

И весь этот путь виден руководителю в одной панели.

```
                    Клиенты
                       ↓

                       ↓
                 CRM + Лиды
                       ↓
              Продажи и заказы
                       ↓
                      ERP
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
 Производство       Склад          Финансы
        ↓              ↓              ↓
     Контроль      Логистика      Документы
                       ↓
                  Аналитика
                       ↓
                   AI RuFlo
```

## 3. Модули системы

### 3.1. Публичный сайт

Первый канал привлечения клиентов: о компании, преимущества мраморного композита,
готовые объекты, производство, каталог, отзывы, контакты.
Формы заявок, кнопка WhatsApp, запрос расчёта, скачивание каталога PDF. SEO-оптимизация.

### 3.2. Каталог продукции

Категории: брусчатка, бордюр, дренажные системы, МАФ, натуральный камень, благоустройство.
У каждого товара: фото, видео, описание, характеристики, размеры, цвета, цена,
наличие, сертификаты, документы.

### 3.3. Лиды (как Bitrix24, но под производство)

Все обращения автоматически попадают в CRM. Источники: сайт, WhatsApp, телефон, email, соцсети.
Система проверяет номер телефона, создаёт клиента (если нового), создаёт лид,
назначает менеджера, создаёт задачу, ведёт историю общения. Дубли не создаются.

### 3.4. CRM

Карточка клиента: компания, контактное лицо, телефон, WhatsApp, email, адрес,
история сообщений, заказы, счета, производство, доставка, документы.
Канбан-воронка, статусы, задачи, напоминания.

### 3.5. WhatsApp через Kelesu

WhatsApp работает внутри системы — менеджер не переходит в отдельное приложение.
Цепочка: WhatsApp → Kelesu → Webhook → CRM → Менеджер.
Сохраняются сообщения, фото, документы, история, ответственный менеджер.

### 3.6. Продажи

Автоматическая цепочка: Лид → Контакт → Сделка → КП → Договор → Счёт → Оплата → Производство.
Конструктор коммерческих предложений: расчёт стоимости, PDF, договор, счёт.
Автоподстановка клиента, товаров, цен, сроков, условий.
Подтверждённая оплата автоматически создаёт заказ в ERP.

### 3.7. ERP — управление заказами и товарами

Система знает: какие товары существуют, сколько стоят, сколько произведено,
сколько на складе, сколько заказано. Статус заказа виден по всей цепочке.

### 3.8. Производство (MES)

Из заказа создаётся производственное задание. Этапы:
Планирование → Подготовка материалов → Замес → Формование → Сушка →
Контроль качества → Упаковка → Готовая продукция.
Простой интерфейс цеха: отметить этап, указать брак.

### 3.9. Технологические карты

Рецепт каждого изделия (цемент, песок, мраморная крошка, краситель, добавки, вода).
Система автоматически считает: расход материалов, себестоимость, прибыль, потребность закупки.

### 3.10. Склад (WMS)

Склады: сырьё, материалы, формы, готовая продукция.
Операции: приход, расход, перемещение, резерв, инвентаризация.
Автоматика: запуск производства → резерв материалов; завершение → приход готовой продукции.

### 3.11. Закупки

Поставщики, цены, остатки, потребности. Контроль минимальных остатков:
«Мраморная крошка ниже нормы — необходимо заказать 5000 кг».

### 3.12. Логистика

Машины, водители, маршруты, адреса. Статусы доставки:
Подготовка → Загружено → В пути → Доставлено.

### 3.13. Финансы

Доходы, расходы, прибыль, платежи, задолженности клиентов.
Прибыльность по заказу/товару/месяцу на основе фактической себестоимости.
Документы: счета, акты, накладные.

### 3.14. Административная панель

Админ управляет всем без программиста: страницы сайта, меню, баннеры, тексты, SEO,
товары, цены, категории, статусы CRM, воронки, менеджеры, склады, рецепты, роли и доступы.

### 3.15. Роли пользователей

| Роль            | Что видит                                                   |
| --------------- | ----------------------------------------------------------- |
| Директор        | Весь бизнес: продажи, производство, расходы, прибыль, долги |
| Менеджер продаж | Клиенты, лиды, сделки, КП, счета                            |
| Производство    | Задания, планы, материалы                                   |
| Склад           | Остатки, движение товара                                    |
| Бухгалтер       | Счета, оплаты, документы                                    |
| Админ           | Настройки всей системы                                      |

### 3.16. AI-помощник (AI RuFlo)

- **Директору**: вопросы на человеческом языке («Какая прибыль за месяц?») — AI анализирует данные ERP и отвечает.
- **Менеджеру**: помощь в ответах клиентам, создании КП, поиске информации.
- **Производству**: прогноз загрузки, анализ расходов, предложения по оптимизации.

Доступ AI ограничен ролью пользователя (менеджер не получит финансовые данные через AI).

### 3.17. Безопасность

HTTPS, роли доступа (RBAC), двухфакторная авторизация, журнал действий,
резервные копии, защита API, шифрование данных.

## 6. GitHub и развёртывание

Проект хранится на GitHub — это единый источник кода. С GitHub проект
разворачивается на продакшен-сервер (Hoster.kz / Plesk). Схема:

```
Локальная разработка (Claude Code + RuFlo)
        ↓  git push
GitHub (репозиторий qazaq-tas.kz)
        ↓  GitHub Actions: линт → тесты → сборка
        ↓  git deploy / webhook
Plesk на Hoster.kz (продакшен)
        ↓
https://qazaq-tas.kz (HTTPS)
```

### 6.1. Правила работы с репозиторием

- Ветка **`main`** — стабильная, всегда готова к развёртыванию. Деплой идёт только из неё.
- Ветка **`dev`** — текущая разработка. Фичи вливаются в `dev`, после проверки — в `main`.
- Секреты (пароли БД, API-ключи, токены Kelesu) **никогда не попадают в Git** —
  только файл-образец `.env.example`; реальные значения хранятся в Plesk и GitHub Secrets.

### 6.2. CI (GitHub Actions)

На каждый push автоматически: ESLint + проверка типов TypeScript → тесты → сборка
`web` и `api`. Если что-то падает — код не идёт в `main`.

### 6.3. Развёртывание на Plesk (Hoster.kz)

1. В Plesk подключается Git-репозиторий GitHub (Plesk Git Deploy, deploy-ключ).
2. Push в `main` → webhook → Plesk забирает код.
3. Скрипт деплоя: `npm install` → `prisma migrate deploy` (миграции БД) →
   сборка Next.js и NestJS → перезапуск процессов.
4. HTTPS-сертификат (Let's Encrypt) в Plesk.
5. Резервные копии БД по расписанию средствами Plesk + дампы MariaDB.

### 6.4. Откат

Любая версия — это commit в GitHub. Проблема на продакшене → откат на предыдущий
commit в `main` → повторный деплой. История версий никогда не теряется.

## 7. План разработки по этапам

| Этап                      | Что делается                                                                                              | Результат                                     |
| ------------------------- | --------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| **0. Фундамент**          | Монорепо, Docker + MariaDB, базовая настройка, **создание репозитория GitHub, первый push, настройка CI** | Проект запускается локально и лежит на GitHub |
| **1. Ядро данных**        | Prisma-схема всех сущностей, аутентификация (JWT), роли (RBAC)                                            | Вход в систему, роли работают                 |
| **2. Админка + каталог**  | Админ-панель, CRUD товаров/категорий, управление контентом сайта                                          | Товары и сайт управляются без программиста    |
| **3. Публичный сайт**     | Главная, каталог, формы заявок, SEO. Заявки пишутся в БД как лиды                                         | Сайт живой, собирает заявки                   |
| **4. CRM и лиды**         | Воронка, автолиды, дедупликация по телефону, карточка клиента, WhatsApp через Kelesu                      | Ни одно обращение не теряется                 |
| **5. Продажи**            | Сделки, конструктор КП (PDF), договоры, счета. Оплата → заказ в ERP                                       | Отдел продаж полностью в системе              |
| **6. Производство (MES)** | Техкарты (рецепты), себестоимость, производственные задания, интерфейс цеха                               | Заказ автоматически становится заданием       |
| **7. Склад + закупки**    | WMS, авторезерв/списание/приход, контроль минимальных остатков, поставщики                                | Остатки точные, материалы не кончаются        |
| **8. Логистика**          | Машины, водители, маршруты, статусы доставки                                                              | Видно, где каждый заказ                       |
| **9. Финансы**            | Доходы/расходы, дебиторка, прибыльность, документы                                                        | Полноценная ERP                               |
| **10. Аналитика**         | Дашборд директора, отчёты, сквозная видимость заказа                                                      | Весь бизнес на одном экране                   |
| **11. AI-помощник**       | Claude API поверх ERP: ответы директору, помощь менеджеру, прогнозы производству                          | «Цифровой завод» с AI                         |
| **12. Запуск**            | 2FA, журнал действий, бэкапы, **деплой с GitHub на Hoster.kz/Plesk**, тестирование                        | Система в продакшене на qazaq-tas.kz          |

Каждый этап заканчивается работающим результатом и push'ем на GitHub.
Деплой на продакшен возможен начиная с этапа 3 (сайт) — дальше система наращивается модулями.

## 8. Запуск локально

```bash
git clone https://github.com/baproger/qazaq-tas.kz.git
cd qazaq-tas.kz
cp .env.example .env        # заполнить свои значения
npm install                 # заодно сгенерирует Prisma-клиент
npm run docker:up           # поднять MariaDB 10.4 и phpMyAdmin
npm run db:migrate          # применить миграции
npm run db:seed             # создать пользователей всех ролей
npm run dev                 # web: http://localhost:3000, api: http://localhost:3001
```

Доступные адреса:

| Адрес                            | Что это                                           |
| -------------------------------- | ------------------------------------------------- |
| http://localhost:3000            | Сайт                                              |
| http://localhost:3001/api/health | Проверка API и базы данных                        |
| http://localhost:3001/api/docs   | Документация API (Swagger, только вне продакшена) |
| http://localhost:8080            | phpMyAdmin                                        |

Порты задаются в `.env` (`API_PORT`, `DB_PORT`, `PHPMYADMIN_PORT`) — измените их,
если порты уже заняты другими проектами.

Учётные записи после `npm run db:seed` (пароль `QazaqTas2026!`, сменить при первом входе):
`director@`, `admin@`, `sales@`, `production@`, `warehouse@`, `accountant@` — все на домене `qazaq-tas.kz`.

### Полезные команды

| Команда               | Назначение                                 |
| --------------------- | ------------------------------------------ |
| `npm run build`       | Сборка всех пакетов                        |
| `npm run lint`        | Линтер                                     |
| `npm run typecheck`   | Проверка типов                             |
| `npm run test`        | Тесты                                      |
| `npm run format`      | Форматирование кода                        |
| `npm run db:studio`   | Визуальный редактор базы данных            |
| `npm run db:reset`    | Сброс базы и повторное применение миграций |
| `npm run docker:down` | Остановить контейнеры                      |
